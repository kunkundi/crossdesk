# CLI 兼容性与使用限制

[返回 CLI 指南](../README.md) · [安装排障](npm-distribution.md) · [终端操作](terminal-client.md)

CLI 目前为开发版。以下用于判断是否适合你的环境，具体发布包仍以其版本说明为准。

## 平台范围

- macOS arm64 已有完整构建、npm 启动和远程连接记录。
- Linux x64 / arm64、Windows x64 是构建与分发目标；完整运行、实际键鼠控制及终端退出恢复仍需在对应设备确认。
- 自行构建的程序可能要求比发布包更新的系统，不能仅按 CPU 架构判断兼容。请核对包内 `build-info.json`。

## 终端范围

| 环境 | 使用建议与限制 |
| --- | --- |
| 普通终端 | 先使用 ANSI；文字细节受字符网格限制，可以放大或缩小字体 |
| Kitty / Sixel | 需要终端通过能力检测；实现协议输出不代表每种终端和版本都兼容 |
| SSH | 分配 PTY，画面刷新取决于网络与终端输出速度 |
| tmux / screen | 使用 ANSI |
| Pi 扩展 | 提供 ANSI 视图；真实 TUI 刷新、增强按键和鼠标传递仍有待确认的范围 |

## 功能限制

CLI 通过设备 ID 控制电脑，默认只读、静音。它不提供 IP 直连、音频播放、文件传输、剪贴板同步或可信设备认证。被控电脑仍需有可捕获的图形会话。

只读是 CLI 的本地输入开关，不是独立的服务端只读权限。终端通常以一次按下并释放的方式发送按键，不能保证持续按键、所有组合键或完整键盘布局都与桌面客户端相同。

`doctor --json` 只检查本机环境，不连接远端，也不证明像素显示或鼠标报告可用。状态栏 FPS 是实际输出计数，静止的 ANSI 画面可以显示 0 FPS，不一定表示断线。

发现问题时，请记录终端名称和版本、系统、渲染模式及复现操作，结合 [故障排查](terminal-client.md#故障排查与边界) 提供反馈。
